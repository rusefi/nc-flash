ECU CAN215 -> TCU request -> CAN216 -> ECU spark (2026-10-06)
===========================================================

Result and scope
----------------
The upstream CAN215 link is now executable. ECU71EC and protected71C4
are encoded into separate words; the TCU subtracts their converted values,
selects/clamps the difference and scales it into request base92E4. The
previously verified phase3 policy and request aggregator then produce
CAN216word0, which reaches ECU spark alongside CAN211. Each feedback case
uses the same ECU instance to produce215 and process returned216, preserving
71C4 as the shared model input. This is explicit function scheduling with
synthetic model/local gates, not a full vehicle or real-time simulation.

Both unchanged ROM hashes and all verification results are in
can215-feedback-verification.json. RAM addresses omitFFFF; code/calibration
addresses are hexadecimal; counts and numeric examples are decimal.

All original numeric/status builders and the packer's critical-section

TCU conversion, subtraction and validity
---------------------------------------
Receive buffer8F2C corresponds to CAN215 in the previously decoded table.
1ACF0 is the complete conversion callback used here. Its call order includes
177DC BEFORE17854. Getter1C866 reads bytes4..5;1C812 reads bytes0..1.
Stock10F38 records5C81A/5C822=01 01 FE 00 and5C5B4/5C5B8=01 0A 00 00
give conversion10*(raw-512). Let clip16 saturate to[-32768,32767]:
  177DC: word4!=FFFF ->88E4=clip16(10*(word4-512)),88E6=2;
         word4==FFFF ->retain88E4,88E6=1.
  17854: word0!=FFFF AND88E6==2 ->
           88E8=clip16(10*(word0-512)-signed88E4),88EA=2.
         Otherwise retain88E8;88EA=1 when word0FFFF or88E6==1,
         else88EA=3 (dependency unready/other status).

The offset is clamped BEFORE subtraction; cancellation is only valid in
the unsaturated domain. For example, equal raw65534 words do not yield0:
the clamped offset32767 is subtracted from650220, then the difference clips
to32767. Boundary pairs test this explicitly. Invalid data holds the old
number with a changed validity; a held number is not a fresh request.
The callback also processes other CAN215 fields with other RAM initially
zero; the new independent assertions concern the offset/difference path.

Feedback and shared CAN211 model
-------------------------------
Seventy-two feedback cases vary input difference0/15/25/35, offset71C4=-5/0/5,
phase3 timer8170=0/5/10 and separate216bit5 cut0/1. The complete sequence is:
  ECU369D6/36A28 ->CAN215 buffer transfer ->TCU1ACF0/516E6/216D8
  ->2C234/1FB8C ->18F10/18F8C ->same ECU CAN216 and CAN211 spark paths.

withdrawal emitsFFFE, decoded by ECU as65022, as in the preceding record.
Diagnostic/local gates are explicit fixtures; the scheduler is not executed.

cases. The SAME offset71C4 also enters ECU CAN211 conversion3F97C, so it can
change CAN211's spark correction even when the returned AT request is equal.

A six-step lifecycle preserves TCU state through fresh25, fresh35, invalid

next step. This does not simulate ECU task history between lifecycle steps.
