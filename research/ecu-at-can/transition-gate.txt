TCU acceptance-gate provenance (2026-10-06)
=========================================

Scope and evidence
------------------
This extends selection-reporting.txt: the unconditional acceptance block at
FFFF9545 mask04 has an identified writer, TCU 2D1BC, called by 2C7B0 at
2C854. The complete original functions execute in verify_transition_gate.py,
including their called helpers. Inputs remain explicit RAM fixtures; this
does not establish physical gear attainment, mode names or scheduler timing.
Both unchanged ROM identities are included in transition-gate-verification.json.

Exact isolated gate behavior
---------------------------
Use unsigned bytes: q = argument r4, p = FFFF954D, a = FFFF9594,
b = FFFF959C, and old = FFFF9545. The resulting mask04 is set exactly when:

  ((old & 4) != 0 OR q in {0, 5})
  AND (q == p OR q == 255)
  AND (a == 2 OR b == 2).

All other bits of 9545 are preserved. The function does not update 954D.
The temporary arming for mode0/5 can be cleared within the same call: a
changed mode that is not FF clears the latch, even if a source equals2.
Conversely, FF can retain an already armed latch but cannot arm it alone.
Getter2F0BC reads9594; getter2F4BC reads959C. These sign-extend their bytes,
but 2D1BC compares them after unsigned-byte conversion.

Whole caller and ECU consequence
-------------------------------
2C7B0 reads8080 and prior954C, selects a local mode via2C892, calls several
policy helpers and can replace the result withFF after2CC70. It sets9545
mask02 forFF; otherwise clears02 and resets81C8. It then calls2D1BC using
the proposed local mode, before storing8080 in954C and the new mode in954D.
This ordering means the gate compares against the previous mode, not against
the value about to be stored. The complete caller executes in paired tests.
Other helper effects and all possible mode-selection conditions are not
independently characterized by this verifier.

The paired path is:
  2C7B0 -> 2D1BC -> 48C08/48174 -> accepted8081/cache606F
  -> 19414(mode1) CAN231 -> ECU35BB8/3585C -> one-hot6ACB..6AD0.

Fixtures set application class8080=6, accepted state0/3/5, requested index
8084=5 and representative previous local modes, source states and old gates.
For these fixtures, an asserted gate retains the old accepted state; clearing
it permits one step toward5. The local mode954D and selection index8081 are
separate variables: matching numeric values do not establish matching roles.

A seven-call lifecycle uses original initializers and2F010/2F222 to set the
two source states from9564=2, then runs the complete caller, acceptance and
CAN reporting. The first two calls hold accepted0 and CAN high nibble1.
Explicitly invoking2F0B0/2F4A8 resets the source states and releases the gate;
five further calls accept1..5 and report CAN high nibbles2..6. Reset invocation
is a fixture, not proof of the scheduler's real recovery condition or timing.
