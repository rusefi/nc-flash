Bounded RTE instruction support
------------------------------
Primary source consulted2026-10-06: Renesas SH-2E Software Manual,
REJ09B0316-0200 rev2.00(2006-05-31), section7.2.48 printed138–139/PDF151–152:
https://www.renesas.com/en/document/mah/sh-2e-software-manual
RTE restores PC and maskedSR(0FFF0FFF) from successive stack longwords,
advancesSP8 and executes the delay slot. Updates precede the slot. Manual
pseudocode PC+4 is its pipeline convention (JMP/RTS use it too); this harness
returns the actual destination, consistently with existing delayed branches.
sh_control_task_dispatch.py adds this only in the local task research subclass.
Aligned RAM frames, aligned ROM destinations andNOPslots only; other frames,
targets andslotinstructions are rejected before state updates. This is a
bounded model, not hardware illegality for every rejected legal instruction.
No exception delivery/priority/timing/interrupt generation or illegal-slot
handler is simulated. Existing shared interpreter andROM remain unchanged.
456 independent instruction cases check allSR bits, PC,SP,otherGPR/GBR/PR,
unchangedRAM anddelay execution;7 expected rejections also preserve state.
All PASS. These checks alone do not prove task scheduling or physical ADCs.
