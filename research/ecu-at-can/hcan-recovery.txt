Register attribution (external source)
--------------------------------------
Renesas SH-2E SH7055S hardware manual, Rev2.00 July2003, sections16.2.1/2,
printed527-529 (PDF566-568), AppendixA printed909 (PDF948), accessed2026-10-05:
https://www.renesas.com/en/document/mah/sh-2e-sh7055s-hardware-manual
The map places MCR at FFFFE400 and GSR at FFFFE401. MCR bits0/1 request
reset/halt. GSR bits0/1/3 indicate bus off, an error warning, and configuration
state. The executable's big-endian word read combines these two bytes.
This is consistent with the previously established SH7055-family map, not
proof of an exact chip variant. Register status is supplied in the verifier;
hardware transitions and CAN error-counter evolution are not simulated.

1A164 recovery task
------------------
Action0 initializes state8BD9=0, retry counter8BCE=0, recovery flag8BCD=0,
deadline8BD4=0, timer mode8BD8=2, and event latch8BCF=0. Action1 processes
the following states and tail-calls diagnostic producer1A4E4(1):

  state0: wait while GSR configuration bit is set; otherwise go to state1
          unless timer mode8BD8==1, in which case go directly to state2.
  state1: event latch8BCF==1 sets8BCD=1 and timer mode1, sets deadline to
          current tick+40 when retry count<10 or+1000 otherwise, goes2.
          Without the latch it clears8BCD and remains1.
  state2: with timer mode1, wait until current unsigned tick>=deadline.
          Then test MCR halt, event latch, or GSR error warning. If any is
          present, set8BCD=1, increment8BCE saturating at255, clear MCR halt,
          request MCR reset and go3. Without these conditions, clear retry/
          recovery state, restore application communication flags, go1.
  state3: release MCR reset and go4 when GSR configuration is acknowledged
          OR after four calls without that acknowledgement (counter8EE0>3).
  state4: wait while GSR configuration remains set. Once clear, rebuild
          outgoing application buffers via19794/197A6, restore communication
          flags, clear event latch, set timer mode1, and advance the OLD
          deadline by40 (<10 retries) or1000 (>=10 retries); go0.

The counter counts the task's retry transitions, not individual bus errors
or necessarily distinct bus-off interrupts. GSR bus-off alone is not tested
in state2; the handler normally supplies the associated halt/event latch.
State4 advances the previous deadline, not current tick: a deliberately late
fixture with old500/current900 gives540 below10,1500 at/above10. Tick wrap
behavior, invocation period and CAN hardware acknowledgement timing remain
unproved. The four-call fallback is a software transition, not a guarantee
that hardware reset completed successfully.
