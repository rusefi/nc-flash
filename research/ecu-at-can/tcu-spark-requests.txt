Records and aggregation
-----------------------
1FB18 initializes five signed-word slots915C..9164 to7FFF, five byte slots
9166..916A toFF,915A to7FFF and80BE to0. Original5BBEC converts software
double0.5 to integer0 on this path; no helper is replaced.
1FB4A(index,value,mode) stores a word and byte in those arrays.1FB6E(index)
resets both to their sentinels. Tests use only valid indices0..4; the simple
underlying indexed writers30652/3064C do not establish general bounds safety.

1FB8C performs these steps:
  1. Stock table5CD0C is00 01 01 00 00. Disabled slots0/3/4 are reset in
     RAM on every call. Slots1/2 are copied to local working arrays.
  2. If slot2 value is0 and slot1 is not7FFF, ignore slot2's value AND mode
     in those local arrays. The actual slot2 RAM is unchanged by this rule.
  3. Helper30686 selects the last non7FFF word, default0. Separately,
     helper3065A selects the last nonFF byte, default0. These are ordered
     overwrite selections, not min/max. Value and mode can come from different
     records when their sentinels disagree; tests explicitly cover this.
  4. If selected mode==1, candidate=base92E4-selected signed word. It tests
     the signed LOW16 bits and clamps a negative result to0. Output915A is
     that nonnegative low word. Other mode values produce7FFF instead.
  5. Inside15A46/15A30 interrupt-mask protection,9158bit0 reflects whether
     selected mode is NONZERO (not specifically1),80BE=-selected word modulo
     65536, and915A gets the result. Other9158 bits and SR mask bits survive.

Signed-word wrap occurs before the lower clamp; this is not a mathematical
unbounded subtraction or an upper saturation. Boundary tests distinguish it.
By contrast, the base conversion described below uses signed saturation.

Base conversion
---------------
216D8 writes both92E2 and92E4 from signed80B4*32/10, truncating division
toward zero and saturating to[-32768,32767] via10D0C. It also converts80B2
into92E6 and updates a92D2 bit fromA528; new assertions cover92E2/92E4.
The paired phase fixtures set80B4=250 and execute216D8 to obtain base800.
Boundary probes corrected an initial assumption of low-word wrapping here:
10D0C clamps explicitly at10D6E..10D7A. No firmware change was required.

Record1 producer and phase3 ramp
-------------------------------
2C234 calls admission2C30C. With class=8080, accepted=8081, code=9B40,
it admits only when class is neither0 norFF,916Fbit0 is clear, code is
neither0A nor11, and either:
  accepted==0 AND class!=1; or
  accepted==1 AND class is neither1 nor2.
512 combinations cover this rule, including high-bit classes. The accepted
index is the already traced CAN231 software state, not physical gear proof.

If admission succeeds and9530bit0 was already set, the caller executes
2C43A, saves its result to953A, then checks continuation in2C400. Otherwise
it may attempt entry through2C370 (entry success remains untested here).
For phase953F==3,2C43A computes signed953C*(953E-8170)/953E via10D0C.
Tests use positive duration10 and elapsed0..10, so this is a nonnegative
truncated ramp. 2C400 ends the request when8171 >= ROM76FF6=122 or when
phase3's result <=0. All900 complete-caller cases include accepted/class,
start-value and timer boundaries. The threshold's wall-clock unit is unknown.

When retained,2C234 calls1FB4A(index1,953A,9542bit0). When withdrawn it
zeros953A/953F, clears9542bit0, calls1FB6E(index1), and clears9530bit0.
It also advances history9532..9538 from80EE. Phase1/2 calculations and the
history/entry conditions are not fully characterized by these tests.
