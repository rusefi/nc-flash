ACKNOWLEDGEMENT CONTRACT (ORIGINAL31524 EVENT3 ->31C18)

Event3 payload contains a big-endian u16 internal group ID, followed by a
byte phase-ring index. These group IDs are application dispatch identifiers;
they are not CAN arbitration IDs.31524 dispatches event3 in state2 only.
Late duplicate event3 payloads while idle state1 are ignored in the tests.

ROM5D3BC lists ten group records, with metadata and periodic class:
  record byte   group(hex)   metadata   period class
       0            05          1            2
       1            06          0            2
       2            20          0            4
       3            0B          0            4
       4            02          0            4
       5            25          0            4
       6            14          0            4
       7            1A          0            4
       8            26          1            2
       9            29          1            2

31C18 marks the matching record byte1 (record base95D4+15*index), when a
matching group is found and index<16. Unknown group IDs add no mark but still
run the completion/retirement scan. The tests use valid indices; this pass
does not claim that arbitrary invalid indices are safely rejected throughout
the function, because later reads use the supplied index too.

If record+14 is zero and all metadata0 groups (bytes1..7) are acknowledged,
31C18 latches+14 to1. This latch alone does not retire the record. Head and
tail retirement also require all ten acknowledgement bytes to be nonzero.
Tests exhaust every0/1 bitmap. No direct check of phase+13 is needed in this
retirement function: synthetic complete acknowledgements retire even phase0.
Actual group lifecycle rules must supply appropriate completion timing.

Retirement order:
  1. Remove consecutive eligible head records, advancing96C4 modulo16.
  2. Remove consecutive eligible tail records without advancing96C4.
  3. A completed interior record waits until it reaches an eligible edge.
Each removal decrements96C5 and calls three5D414 callbacks in order, passing
the record's transition code:30B82,30A9E,31168. Empty count resets periodic
phase96C6 and returns1, updating dispatcher8088 to idle. Nonempty returns-1
and retains the dispatch state. Original record bytes are not erased at
retirement; ring membership/count and dispatch state govern their use.

The callbacks restore capture state:30B82 conditionally sets95C2 to1 for a
matching95C4 code;30A9E conditionally sets95BE to1 for matching95BF;31168 sets
nonzero95D0 to1. Their full bodies run in the tests; no callback is stubbed.

31F64 creation(kind0) notifies all ten groups. Phase completion(kind3)
notifies unacknowledged metadata0 groups. Original generic manager cleanup
also sends group1/event3 acknowledgement messages after managed-request
release. This provides the missing original-code path from group8 release
and the remaining phase-controlled groups to final retirement.
