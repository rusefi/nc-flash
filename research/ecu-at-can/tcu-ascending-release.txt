Result
------
Original group7 release callback4E0EE scales a captured request with the
remaining measured-minus-reference error. It is not a timer-only fade and is
not necessarily monotonic: a larger subsequent error can restore a request
after it reached zero. Unlike activation4E036, release does not recheck9410
bit0 or92D5 bit0. Outer manager cancellation remains a separate mechanism.

A retained original manager trace now activates1280, releases through510 and
260 to zero, and retires normally at fixturecall142. Paired ECU calculated
spark follows21,22,23,26 using explicit test coefficients. This distinguishes
numeric withdrawal (call96) from phase completion and final retirement.

Helper and calibration semantics
--------------------------------
4E2D6(index): error=clamp(s32(s16(80EE)-s32(9218[u8(index)])), -32768,32767).
The subtraction wraps as32-bit before the clamp.196 tests cover seven indices,
signed measurement boundaries and extreme reference/wrap cases. Not all test
references are reachable from the stock upstream reference producer.

10D0C(numerator,denominator): signed32/signed16, truncation toward zero then
signed16 saturation. A zero denominator produces0 for numerator0,32767 for
positive numerator,-32768 for negative numerator.25 helper cases execute it.

4E450 produces two bounds. Bank=code0..4 or fallback0:
  lower = s16(ROMword[76742 +12*bank +2*u8(record+12)])
  axis =208F0(s16(80EA)) =4*clamp(s16(80EA),0,16383)
  factor = u16(curve[767D8+9*bank](axis)) >>8
  dynamic = s16(-s16(80F0))*factor
There are six lower-bound words per bank, all51 in the stock ROM. Only those
six slots are covered by this table oracle;4E450 itself does not check that
the selector is in0..5. Physical/upstream selector validity remains open.
The signed-word negation wraps: negating0x8000 remains-32768 for MULS.W.
Code1 factor is always3; code3/4 always1. Other curves depend on the source.
Tests cover signed axis/saturation boundaries and the negation edge.

4E4DE selects two shape bytes, each returned as a word:
  side = u8(record+12) >= ROMbyte[773F0+bank]  (stock threshold2)
  knee = ROMbyte[768FF+2*bank+side]           (stock0)
  slope = ROMbyte[76909+2*bank+side]          (stock64)
All256 selector values and codes0..5/255 execute this helper. Both sides of
every stock pair are identical. Since progress is clamped0..256, progress<knee
cannot occur with stockknee0. Alternate first-segment calibration behavior
is retained in disassembly but is not claimed verified by the stock tests.

Full stock release model
-----------------------
Read error through4E2D6 with target index ROMbyte[5D446+record.code].
If error<lower OR error<dynamic, candidate=0. No capture occurs on this path.
Otherwise:
  ratio = div16(error*256, s16(record+10))
  progress = clamp(256-ratio,0,256)
  if record+8 bit0x40 CLEAR:
    record+6 = record+4
    record+8 |=0x40
  candidate = max(0,div16(s16(record+6)*(256-progress),256))

The model reflects the original stock second segment. Software multiply10C4C
at shift0 precedes the second division; its values here fit signed32. The
initial div16 quantization matters: error100/captured250 gives ratio102,
progress154;1280*102/256 truncates to510, not512.
Captured error zero saturates the ratio when positive, producing progress0.
A negative captured error yields clamped progress256 and candidate0. These
are deliberate boundary fixtures, not assertions of normal state reachability.

The callback stores candidate into word+4, sets bit0x80 for positive output
or clears it for zero, preserves other flag bits, and calls4C6DA to update the
allocated request list. It does not consult activation9410/92D5 gates. Twelve
combinations (9410=0/1/6/7,92D5=0/1/FF) all produce320 for the same admitted
release fixture. This is callback-level evidence; cancellation916F/outer state
logic can still prevent invocation or release the request entirely.

4C7AC/1FB8C then produce915A=max(base800-candidate,0) for an active positive
candidate. Candidate0/mode0 produces sentinel7FFF. Candidate7FFF is also
treated as sentinel, even though callback bit0x80 is positive. A first oracle
incorrectly treated every positive candidate as active; the32767 boundary
test exposed that and the oracle now accounts for the existing sentinel.
Stock map candidates in this investigation are much smaller than32767.
