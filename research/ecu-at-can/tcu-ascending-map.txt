Numeric calculation4E3A8
------------------------
Bank=code for0..4, otherwise0. All offsets below are ROM addresses.
  threshold = u16BE(76738+2*bank)
  map =76805+50*bank
  scale curve =76913+9*bank
  base = u16(1078A(u16(80F8),u16(record+18),map)) >>2
  if record+8 bit0x10 CLEAR and u16(record+16)>=threshold:
    factor = u16(10764(u8(8276)<<8,scale_curve)) >>8
    result = (base*factor)>>4
  else result=base

Stock threshold words:38400,13312,38400,38400,38400 (decimal).
The comparison is effectively unsigned16; values above32767 are not negative.
All five maps are6x6 byte-axis/value tables (each byte scaled256 by helpers).
The full curves are saved in the ROM; timer knots and integer factors are:
  bank0/2: knots0,3,6,12 -> factors6,11,16,16;
  bank1:   knots0,3,4,6  -> factors0,2,10,16;
  bank3/4: knots0,2,5,12 -> factors8,13,16,16.
This is initial attenuation that rises to full value, not a decay curve.
Bit0x10 bypasses the scaling, and a captured value below its threshold also
bypasses it. Live80F8 is read at every call; the second map axis is captured.

Callback4E036 and arbitration
----------------------------
It calls4E3A8, then suppresses the candidate if92D5 bit0 is set OR9410 bit0
is clear. Positive candidates set record+8 bit0x80; zero clears it. Other bits
are preserved. It stores word+4 and calls4C6DA(handle,value,positive_flag).
The odd-looking software-double branches convert+/-0.5 to integer0; they do
not add a half-unit to the calculated request. Original helper execution checks

Produced permission sequence
-----------------------------
Original23BF6 runs with916D fallback off. Bit0 lower threshold comes from
700C8(80C8)>>1 and broad threshold from700D3(80C8)>>1. It clears bit0 only
when809C<broad AND809A<lower; sets it when809A>=lower+512; otherwise holds.
At80C8=16000, lower96 and broad5984. Starting9410=6, inputs(809A,809C):
  (0,20000) -> bit0 clear;
  (25000,20000) -> bit0 set;
  (0,20000) -> bit0 retained;
  (0,0) -> bit0 cleared;
  (25000,0) -> bit0 set again.
Each update is followed by the actual numeric callback/arbitration and paired
ECU verification. This explains why changing809A alone need not disable an
already enabled request. Other9410 bits still follow their own hysteresis.
