ECU model sources, stock maps and paired CAN feedback (2026-10-06)
===============================================================

Result and limits
-----------------
The ECU's actual stock model maps and source producers now execute before
CAN215 publication and the TCU's returned CAN216 request. The same model
coefficients and offsets also feed the CAN211 inversion/spark path. Earlier
feedback tests seeded these model values directly; this follow-up resolves
those immediate writers and calibration selection, including a count producer.
Raw sensor/state inputs, TCU active phase3 and task order remain fixtures.
It is not a complete ECU scheduler or physical vehicle simulation. Physical
wire units, CAN211 sender, the upstream pattern-index policy, complete traction
actuation, and PRHT signal/state integration remain unresolved requirements.

Input ROMs and hashes are recorded in model-sources-verification.json. Both
original images remain unchanged. All addresses/masks are hexadecimal; case
counts and numeric formulas use decimal. RAM addresses omitFFFF.
Reproduce: python research/ecu-at-can/verify_model_sources.py

Interpreter support and verification
------------------------------------
sh_model_float.py is separate from all earlier interpreters. It adds MACH
stack save/restore, signed16 multiply and finite FNEG to bounded normal RTZ
FPU support.320 transfer,1280 multiply and96 negation vectors pass;4 deliberate
subnormal/nonfinite negations are rejected. SR and unaffected registers are
checked. Full FPSCR exception/interrupt behavior remains outside scope.
The initial stock lookup failed at unsupported STS.L MACH2372; after adding
save/restore and MULS.W, stock-model final output reached unsupported FNEG
at8B3B2. Neither helper was mocked or bypassed; both now execute and pass.
Reference consulted2026-10-06: Renesas SH-2E Software Manual REJ09B0316-0200,
LDS printed102..103,STS154..155,MULS.W126,FNEG194:
https://www.renesas.com/en/document/mah/sh-2e-software-manual
These define register transfers, signed16 multiplication and finite sign
negation. Existing RTZ limits and arithmetic verification remain unchanged.
No older verifier or shared interpreter was modified; no redundant full
research-suite rerun was needed. New evidence tests pass with unchanged ROMs.
