Original list mechanics
----------------------
30454 creates4-byte nodes:previous byte,next byte,signed value word. With
stock descriptors,node0 is the active-list head,node1 the free-list head.
First bank entries are2..13;second bank entries2..4. Activehead starts as a
self-loop;freehead initially links every available entry. All values are7FFF.
Bankinitializers clear mode arrays and seed their published word7FFF; they
do not explicitly reset the bookkeeping counters in the inspected bodies.

304C6 allocates the first free node and inserts it at the tail of the
requested priority list. Wrappers receive priority1, which maps to head0.
The verifier never claims valid behavior for other priorities in these
one-priority stock lists.305D0 unlinks a node;305F0 inserts before a head.
30518 writes its word;the bank wrapper writes the parallel mode byte.
30524 unlinks and returns an entry to the free-list tail, resets its word
to7FFF;the wrapper clears its mode and decrements bookkeeping.

Full allocation returnsFF when no free node remains, but the bankwrapper
still increments bookkeeping:12->13 and3->4. The test verifies this result
without passingFF to an unchecked setter. Do not infer a vehicle fault or
out-of-bounds write without checking actual callers' handling of failure.
Valid release/reuse follows FIFO free-list order.600 deterministic operations
(seed216) check both directions of every list link, counters, selected index,
value/mode and final slot2 against independent Python queue models.

3054E scans priority heads from high to low, walking allocation order in each.
In the stock single-priority lists it returns the first nonsentinel value,
not a maximum/minimum across all nodes. When all active values are7FFF,
the selected index is the LAST visited active node, so its mode is retained.
An empty list returns7FFF withindexFF;the bankreader then suppliesmode0.
Tests distinguish an empty bank from an active sentinel-valued entry.
The generic multi-priority case is not independently characterized here.

4C7AC merge and record2 publication
---------------------------------
The full caller executes both readers,then snapshots first/second values
toA204/A206 and modes toA208/A209. LetA,B be signed16 values andma,mb bytes:
  Ifma==mb:chooseB only ifA<B AND B!=7FFF;otherwise chooseA.
  Ifma!=mb:chooseB andmode1 only ifmb==1;otherwise chooseA/modeA.
  If chosen value==7FFF:reset record2 through1FB6E.
  Otherwise:set record2(value,mode) through1FB4A.
  Publish chosen rawword to80E4 regardless of record reset.

Thus a first-bank sentinel can dominate a valid second-bank value when
modes match. With different modes,second-bankmode1 takes precedence even
if its value is7FFF, withdrawing an otherwise valid first-bank request.
Tie values retain the first bank. These are signed comparisons,not unsigned
maxima.841 combinations cover empty banks,0,1,320,640,7FFF,8000,FFFF values
and0/1/2/FF modes using real allocation and setters, without editing links.
