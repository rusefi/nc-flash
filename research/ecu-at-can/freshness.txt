TCU: APPLICATION RECEIPT TO DEADLINE AND FAULT BITMAP

All addresses in this section refer to LFG1TF000.bin. RAM has FFFF prefix;
ROM values/addresses are hexadecimal except explicitly decimal tick counts.

Admission1BF38 accepts application indices0..9 only when8F6C has bit04 or08
set; it then sets pending byte8F71. Diagnostic indices10/11 are accepted
without that application gate and do not set8F71. Tested48 combinations.

The RX path1B768 sets a receipt bit at8F4E plus ROM5C950[index], using mask
5C95C[index]. Offsets are0 for indices0..7 and1 for8..9; masks are successive
bits. The controller ISR itself has not been emulated.

Dispatcher1BD10 requires8F71!=0, clears it, checks8F6C bits0C, consumes each
pending bit, and calls table5CA10[index]. This is dispatch, not a timeout.
CAN211 logical index7 invokes1C242: sets0C in both8F87 and8F8D, then1ACEC.
The complete211 callback executes in the harness. Other callbacks include
conversion helpers not yet executable in the integer subset; do not claim
all ten payload-processing callbacks have run end-to-end.

Receive watchdog19AF0 requires8F6C bit08. For each monitored record, it calls
1C018 with a field number. That helper reads and clears one bit from8F82,
using offset table5C9A0 and mask table5C9CF. On receipt, watchdog19AF0 calls
19D44(record,slot0) to refresh the deadline, then19DC0(record) for recovery.
With no receipt, it calls19E10(record), which checks expiry via19D04.

TCU table5C610 has eighteen28-byte records, distinct from hardware mailbox
indices and the logical receive-copy indices. Record+0 is ID; +8 and+10 are
two u16 intervals; +13 is a classification byte. Both interval slots are
executed, but receive watchdog19AF0 specifically uses slot0.

19D44 stores tick84D0 + interval at8B38 + 8*record + 4*slot.
19D04 returns1 for unsigned current_tick >= stored_deadline, including
equality. Boundary tests cover18 records x2 slots x3 times =108 checks.
No conversion from ticks to milliseconds is established. The direct unsigned
comparison has not been assessed against the global tick-reset/wrap policy.

On expiry19E10 refreshes the deadline and invokes1A454 with action7,6,5 for
classes0,1,2 respectively. 1A454 routes to1A598 action15 and group36,37,38;
that branch ORs 1<<record into shared word8EE2. This is a software fault
bitmap, not by itself a final DTC, transmission fallback or torque action.

On receipt19DC0 performs recovery only while byte868C!=0. It chooses actions
4,3,2 by class, reaching1A598 action14. That clears the corresponding8EE2
bit and resets additional per-record diagnostic state. If868C==0, receipt
still refreshes its deadline, but this path preserves the fault bit.
Static initialization trace:15574 clears868C at15582 and sets it1 at15710
after initialization, alongside868D. This supports an initialization gate;
the initialization routine itself is not emulated. MOV.W sign-extended
literal references at15578/1570C/19DC8 locate these accesses; searching only
32-bit address literals misses them. Later DTC qualification remains open.

All ten monitored records were exercised at receipt, one tick before expiry,

For211, admission -> receipt dispatch -> watchdog -> expiry -> recovery was

  tick100 receipt: deadline110, bitmap0000
  tick109 no receipt: deadline110, bitmap0000
  tick110 no receipt: deadline120, bitmap0004
