Conventions
-----------
All short RAM addresses have FFFF prefix. R(x) denotes binary32 rounding
toward zero after each operation. Values and counts have no assigned physical
units or milliseconds. Mode734A bit40 is the established MT configuration
bit; its absence alone does not prove a functioning AT system.

Source countdown: 58B9C
----------------------
  if raw7010 == 1: 80A8 = byte[DA03C]
  else:           80A8 = max(0, old80A8 - 1)

Stock DA03C is zero. Starting at zero, this producer never makes the counter
nonzero. Direct nonzero-count tests exercise its consumer branches; they do
not establish a normal production route into those branches.

Target production: 58BD0
------------------------
The target 80A0 clears to zero if any of these is true:
  raw7346 == 1; rawA3A4 == 1; both raw80A8 == 0 and raw7012 == 0.
The disabled branch holds 80AC,80B0 and80B8; it does not clear them.

Otherwise select a 7-by-9 map:
  A3628 when 734A bit40 is set OR raw7EEE > 0;
  A363C when the bit is clear and raw7EEE == 0.
Both use x=6DB4 and y=6CD4. x knots are 1000..4000 by500; y knots are
0..50 by6.25. A3628 values are approximately .005..017; A363C values are
0..approximately .05. These are actual stock tables, not substituted maps.
80AC stores the bilinear result.

6D28 selects a lower interval index from [-40,-20,0,20,40,60,80,100], clamped
to0..7. Exact knots select their new interval. The byte index goes to80B8;
80B0 receives the corresponding DA1DC value. This is a stepped selection,
not interpolation through descriptor A361C. Every stock factor is100.

  80A0 = R(R(80AC * 80B0) / 100)

Keep both rounded operations even with stock factor100: the resulting float
need not equal80AC bit-for-bit. The tests check side outputs as well as80A0.

Retained rise and scaling: 58D44 and58B78
---------------------------------------
58D44 clears809C when A3A4 == 1 or both7012 and80A8 arezero. Otherwise:
  809C = max(old809C, 80A0)

This routine does not test7346. Consequently7346 == 1 clears the target in
58BD0 while the rise routine can retain a previously larger809C. Separate
decay then controls its decline. Raw7012 == 2 enables this path, whereas the
previously verified 587A2 limit producer requires exactly1.

58B78 computes80B4 = A35E0(6D5C), then8098 = R(809C * 80B4). The seven stock
knots span0..approximately22.608, with every value1. The complete lookup
still executes. Thus finite stock inputs pass809C through to8098.

Previously verified58F10 consumes8098 in:
  80C0 = max(813C, R(R(8098 * 6DB4) / 7020))
and includes80C0 in the baseline sum80BC. Its near-zero7020 hold still applies.
The baseline then feeds the history, ratio and command paths already recorded
in control-input-history.txt and control-ratio-inputs.txt.

Decay selection and application: 58DD8 and58E68
----------------------------------------------
58DD8 chooses the first applicable speed-indexed curve, writing80A4:
  80A8 > 0 AND7010 == 0: A35EC, every value approximately15.999.
  Otherwise7EEE != 0: A35F8, approximately.002 through2500, .03 at3000,
    .05 from3500 onward.
  Otherwise75DC == 1: A3610, approximately.001 at500/1000, 1 from1500.
  Otherwise: A3604, approximately.00168 at500, .002 at1000..2500,
    1 from3000 onward.
All four curves have ten x knots500..5000 by500 and interpolate between them.
The large first curve requires a nonzero countdown that the stock countdown
producer does not create fromzero; reachability remains distinct from execution.

58E68 first clears809C when bit40 is clear and old809C < stock DA040 = 0.
Otherwise:
  floor = 0 if7346 == 1, else80A0
  809C = max(R(old809C - 80A4), floor)

The subtraction can lower a retained overshoot but cannot cross the current
floor. With7346 == 1, it can return towardzero despite an old nonzero target
fixture. In stock production58BD0 also clears the target under that flag.

Local caller order and integration limits
-----------------------------------------
Caller1A604..1A618 runs countdown -> target -> rise -> scale. Five other calls
at1A61C..1A638 intervene before baseline58F10 at1A63A. Those bodies remain
outside this test. Caller1B862..1B86A runs decay-step selection -> decay.
The relative rate/phase of the two tasks remains unverified.

The retained lifecycle initializes809C through its original clear branch;
it does not directly inject809C,8098 or the target after initialization.
Other baseline contributions and input/status values remain explicit fixtures.
The source group runs before the previous baseline/history/ratio chain; decay
and protected history publication run once at the end of each synthetic cycle.
This chosen scheduling is not a claim about real task frequencies.

The lifecycle raises the AT-map target, lowers it with changed inputs, clears
the target with7346 while allowing decay, selects the alternate map through
7EEE, exercisesA3A4 and7012 clear branches, and admits raw7012 == 2. Produced
8098 feeds the original baseline calculation and subsequent paired path.
At call11 the target rises from approximately.02 to.05. At call21 it falls
to approximately.04 while the used source remains.05, then decays to.048.
At call31 the target clears tozero while the used source remains.04, then
decays to.038. These are invocation counts in the synthetic schedule.
The selected command is capped at16.5 in this fixture; the trace does not
demonstrate varying physical actuation from these source changes.

Important fixture boundary: publish() in verify_control_conversion.py writes
A3A4 = 0 on each paired CAN update. The call61 injectedA3A4 == 1 therefore
clears the source for that pass, then the helper resets the gate. Saved rows
record source_gate_before/after. This is a test action, not evidence that CAN
firmware writes or clearsA3A4. Earlier exploratory interpretation of that
change as firmware behavior was rejected after inspecting the helper.
