2026-10-06: ascending phase qualification and initial-delay policy
================================================================

Result
------
Original ascending phase qualification has two routes with separate per-record
counters and a shared lower-threshold crossing flag. For codes0/1, mode8086=0
counts samples below the upper threshold, including samples below the lower
threshold. Completion additionally requires a remembered lower crossing.
Mode8086=1 instead counts samples inside the band. Codes2/3/4 use the band
regardless of mode. Other mode values admit neither route for codes0/1.

This explains the retained code1 trace:79 samples accumulate before the first
lower crossing; call80 immediately qualifies phase0 through its target route.
The rebound above the upper bound resets the counter but sets the crossing
flag. After20 subsequent below-upper samples, phase2 is reached at111, well
after numeric request withdrawal96. Final retirement remains142.

Initial-delay317E4 is also verified for ascending records, including neighbor
and preceding-slot branches. The ordinary stock delay is18 signed timer ticks;
it is not an unconditional requirement because target qualification provides
a separate phase0 admission route. Counts/ticks are not physical time units.

Ascending initial timer317E4
----------------------------
For record index i, code0..4 and captured selector808D:
  delay =ROMbyte[70A6C +6*code +u8(808D)]
Stock five rows each have six entries, all9. The final comparison is signed
timer8380[i] >=2*delay. Negative timer values reject even if delay becomes0.

The routine reads preceding/following physical ring slots with modulo16 wrap.
Let position=(i-head96C4) modulo16 and following=(i+1) modulo16.
Delay becomes0 if position+1<count96C5 AND following code is ascending AND
signed timer8380[following] >=2*its own calibrated delay using the same808D.
It does not examine that following record's phase byte in this decision.

Another zero-delay route: current operation byte+11 is nonzero AND the
preceding physical slot's code is classified descending (code not0..4).
There is no check that the preceding slot is currently an active predecessor.
At the ring head, including a single-record ring, retained preceding-slot
code can therefore affect this branch. This is a verified memory dependency,
not proof of a firmware bug or a reachable unsafe overlap.

Tests cover allfive codes/six selector slots, single/head/tail positions,
indices0/15, ascending/descending neighbor codes, next-timer17/18 boundaries,
nonzero operation and signed current timers. When the following slot lies
outside the active count, its readiness does not bypass the delay. The
preceding-slot operation route has no corresponding active-count condition.
Original arithmetic helper converts+0.5 to integer0 on those bypass branches.

Ascending qualifier32614(index, code, operation)
------------------------------------------------
Measurement is signed16(80EE); bounds are signed32(9704/9700).
First, if measured>=lower, set shared971A bit1. This happens even above the
upper threshold, and even when the selected mode permits neither route.

Band route eligibility:
  codes2/3/4, OR codes0/1 with8086 exactly1;
  lower<=measured<upper.
Eligible calls increment byte96CF[index] with saturation255; others reset it0.
Counter threshold pairs in70B06, selected by9410 bit0:
  code       bit0 clear    bit0 set
    0           30          100
    1           20           20
    2           30           20
    3           10           10
    4           20           20
Operation argument0x12 or0x13 substitutes ROMbyte770BE=20 for this route.
This is the function argument, unlike the global9C88 override in the older
descending qualifier. Other9410 bits do not affect the selected column.

Below-upper route eligibility:
  codes0/1,8086 exactly0, measured<upper.
Eligible calls increment byte96DF[index] with saturation255; others reset it0.
Threshold pairs70B10 are code0:20/25, code1:20/20, again selected by9410bit0.
There is no operation12/13 override here. Counter completion also requires
971A bit1, whether set this call or remembered from an earlier one.

Return1 if either route completes, else0. Success clears971A bit1 but leaves
both counters at their resulting values. Other971A bits are preserved.
Equality atlower is eligible; equality atupper rejects both measurement routes
but can set/retain the crossing flag. Neither counters nor the flag represent
a fixed time duration without the actual task scheduling context.

Retained behavior and shared state
----------------------------------
Direct code0/mode0/bit0clear probe starts lower872/upper1128, flagclear:
22 calls at800 accumulate counter22 without completing. One call at1200
sets the crossing flag and resets the below counter.20 more calls at800
complete at call43 despite all20 being below the lower threshold. Success
clears the flag; another800 call does not complete, a1000 sample sets it and
completes again at45, and a final800 sample again cannot complete.

The crossing flag is global, while96CF/96DF are indexed. A three-call probe:
  index0/code0/mode0 belowlower reaches count20 with flagclear -> no success;
  index15/code2/mode1 aboveupper sets globalflag, its own counters0 -> no success;
  index0/code0/mode0 still belowlower increments to21 -> success, consumesflag.
This proves interaction between interleaved original qualifier calls, not a
complete two-transition ring/dispatcher lifecycle. That broader overlap test
and the flag's other producers/clearers remain open.

Mode2/code1 can set the flag while resetting both ineligible counters. Switching
to mode0 then permits completion after20 below-lower samples using that remembered
crossing. Thus a mode change does not itself clear crossing history in32614.
