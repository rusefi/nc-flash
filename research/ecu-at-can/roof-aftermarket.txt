NC PRHT signal corroboration from public aftermarket firmware, 2026-10-06

RESULT AND EVIDENCE BOUNDARY

Openhoonage NC Cluster Commander 1.01 provides independent corroboration for
CAN231 selector codes1=Park,2=Reverse,3=Neutral,4=Drive. Its own menu labels
those states, and its original AVR builder places them in payload byte0.
This agrees with the ECU/TCU grouping of1/3 already executed in
selector-inputs.txt. It strengthens the P/N interpretation, but does not
prove PRHT reception, roof permission bytes, physical TCU pin assignment,
or OEM equivalence of the rest of this aftermarket frame.

The public image is an aftermarket GM-to-NC-cluster converter, NOT Mazda
PCM, TCU, DSC or PRHT firmware. It is older than the author's announced
PRHT-support update. No roof-controller binary or vehicle capture was added.
All three goals remain active: ECU/AT integration, deep traction integration
and NC PRHT folding/unfolding CAN. No CAN open/close command is established.

ORIGINAL AVR SELECTOR BODY EXECUTION

All addresses in this section are AVR FLASH BYTE addresses, NOT SH addresses.
Function199C allocates a16-byte temporary frame. The bounded harness starts
at19C4 after its prologue with synthetic Y=0600 and r1=0. It executes all
body instructions until1A26, immediately before the call to1166. The
interface pointer is032E; registers8..23 hold this by-value record:
  +0..3 little-endian identifier00000231
  +4 zero (standard identifier branch)
  +5/+6 untouched stack contents
  +7 length8
  +8..15 payload bytes0..7
SRAM0272 supplies the converter's selector state;0273 supplies its gear byte.
  Selector0..4: payload0=selector,payload1=0
  Selector5: payload0=4,payload1=80
  Selector6: payload0=4,payload1=40
  Selector7..255: payload0=0,payload1=0
  All cases: payload2..6=0,payload7=SRAM0273 unchanged
Thus do NOT transfer this converter's forward-gear location to the OEM TCU,
whose full CAN231 publication is documented separately. Only the shared
low-nibble selector convention is corroborated here.

Static menu cross-references258A..263E compare the SAME SRAM0272 with1..6
and print strings atB0F/B07/AFF/AF8/AF0/AEC respectively:
  1 Park;2 Reverse;3 Neutral;4 Drive;5 Manual;6 AT.
String bytes are verified; branches and argument construction are preserved
in roof/converter-excerpts.txt for independent static review. The menu body
itself is not executed by this harness.

verify_roof_converter.py executes65536 selector/gear pairs,512 additional
scratch-content cases and4 expected fail-closed rejection cases. It decodes
original LDI,CPI,LDS,LDD/STD Y+q,BRBC andRJMP opcodes. Only consumed C/Z flags
are modeled. Unsupported instructions, branch flags, PC ranges and memory
accesses reject. Independent output formulas check the whole outgoing
argument record, including preserved stack bytes, not just selector0.
Results and sample payloads are in roof-converter-verification.json.
No prologue/epilogue, scheduler, interrupts, SPI, CAN or PRHT is executed.
No general AVR-emulator accuracy is implied by these bounded tests.

STATIC TRANSPORT AND SPEED LEADS (NOT NEW EXECUTED WIRE PROOF)

1166 stores the by-value record, uses standard identifier bits at11DA..11F6,
then emits MCP2515-style load-buffer headers and payload through SPI helper
D3A. Standard231 implies SIDH46/SIDL20. It selects a TX buffer via110E and
requests transmission with81/82/84 at12B0..12C6. Primary MCP2515 DS20001801K,
registers3-3/3-4/3-7 and section12.6/12.7, supports that interpretation:
https://ww1.microchip.com/downloads/aemDocuments/documents/APID/ProductDocuments/DataSheets/MCP2515-Family-Data-Sheet-DS20001801K.pdf
Important audit limits: the builder leaves record+5/+6 uninitialized. Sender
11F8..1200 uses+5 in its DLC byte arithmetic (8 -128*byte modulo256), and
payload loop1282..129A appears to iterate0 THROUGH length inclusive. Neither
quirk is repaired, hidden by zero-filled scratch, nor tested on hardware.
Do not call these bounded argument tests a validated wire transmission.

17EC constructs standard201 length8 and the same interface032E. Its
candidate speed field is payload4/5, big-endian after helpers fed by SRAM0269.
The menu labels0269 as MPH and calls integer division with100 at24F2..24FE;
the201 builder uses binary32 constants3FCDFEDA (~1.60934) and461C4000(10000)
at186A..187E. This supports the stock ECU201 speed hypothesis and motivates
checking km/h hundredths plus10000, but those software float helpers and
their rounding/range behavior are NOT executed/fully identified here.
Keep exact physical scaling and OEM PRHT use unproved. Existing original
ECU4B0/216->201 arithmetic remains authoritative in can201-speed.txt.

features; do not assign opposite-button behavior to the OEM state machine.
The identical guide was initially found on a reseller mirror; first-party
link above is now available. No CAN IDs/bit fields are published there.

RCNC-2 guide Rev1.3,2025:
https://cdn.shopify.com/s/files/1/0014/3779/4419/files/RCNC-2_User_Guide.pdf?v=1719695390
This newer generation retains one-touch/speed/reverse/automatic features

image. The current linked Windows ZIP contains one633192-byte executable,
not a separate HEX/BIN. Archive members/hashes and exact URL are recorded
in roof/download-manifest.json. The executable was not run or inspected for
embedded firmware; its lack of a separate image is not proof none exists.
The older guide's instruction to select Update.hex does not establish that
the current newer-generation ZIP contains the older firmware.
