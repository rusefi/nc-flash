CAN201/CAN215 input faults, shared substitution and recovery
Evidence checkpoint: 2026-10-06

VERIFIED RESULT

An invalid CAN215 byte6 can substitute three TCU application inputs, including
ones sourced from a healthy CAN201 message. Immediate received-value holding
and later diagnostic substitution are separate stages. A return to valid
payloads restores the decoded numbers before the application substitutions
clear. CAN201 byte6 invalidity has the same shared application consequence.

This extends tcu-paired-input.txt through produced diagnostic state instead
of an injected92D5 fault flag. Existing can201-byte6/selection-pipeline work
already established aggregate-to-flag mapping. The new evidence executes
group3D qualification/recovery and both paired input producers together,
including independent and simultaneous faults, interrupted recovery and
switching the failing message while the shared application fault stays set.

The encoder fixture supplies CAN201 source78 and CAN215 source60. It runs
both original ECU encoders on one ECU instance, changing A3A4 between the
two publications for isolated-invalid tests. That explicitly represents a
change between message publications; it does not assert two independent
A3A4 values at one instant. Shared-invalid tests keep it1 for both encoders.
Other CAN215 numeric words remain valid because their6E2E invalid flag is
separate. Payload buffers are transferred explicitly; no CAN ISR is simulated.

Both isolated CAN201 and simultaneous faults follow the same shared policy.

Switching from qualified CAN215 invalidity to CAN201 invalidity at601 lets
group3C qualify at1101 while3D is recovering. Clearing3D on the second1101
pass leaves the shared fault asserted by3C. Only after3C's healthy period
and next producer pass do all three healthy application values return.

A valid sample before qualification cancels that invalid interval. A fresh
invalid sample at600 then qualifies at1100, not the abandoned600 deadline.
Invalid or explicitly injected unready validity3 during recovery restarts
the healthy interval. Dependency masksA977/A978 bit3 suppress the group3D

when admission returns. These are producer-gate fixtures, not claims about
the complete communication-loss/recovery controller in the same test.

No serialized558CC report, CAN216 reportbit1 or CAN231 byte1bit6 appears in
these isolated data-invalidity lifecycles. That limited absence does not
mean normal application control or absence from every diagnostic service.

HARNESS CORRECTION

The first retained-manager experiment also passed original instruction
observers but failed the older healthy-sequence assertion. Inspecting its
trace exposed an extra validCAN215 byte6=0 reception from the helper before
the intended invalid frame atcall100. That overwrote the value being held.
The corrected hook owns every CAN215 update; it asserts880C remains975 on
every pass and checks the pre-qualification application value. The earlier
trace is rejected as evidence for uninterrupted invalid-value retention.
The matched healthy control uses the same full diagnostic/input pipeline.
